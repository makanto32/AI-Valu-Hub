Design intent: keep conversation flow resilient even if cloud persistence or AI enrichment is unavailable, while enabling richer enterprise behavior when Azure dependencies are configured.

1. System Overview

The solution combines a guided business conversation UX, a deterministic skill orchestrator, and optional AI enrichment to move from raw opportunity intake to architecture deliverables.

Business User

Submits ideas through a natural conversation flow and sees structured feedback immediately.

React + Vite Frontend

Delivers the guided UX, stage-specific views, and embedded architecture outputs.

FastAPI API Layer

Handles orchestration, policy checks, persistence calls, and tool coordination.

Skill Orchestrator

Routes the conversation to the right skill or agent based on stage, role, and context.

Domain Skills Registry

Catalogs business, technical, and architecture skills plus their prompts and instructions.

Knowledge Persistence

Stores session state, context, decisions, and artifacts for progressive enrichment.

2. End-to-End Flow

Conversation remains organic, but each stage is explicit and persistable.

Step 1

Business Intake

User describes the opportunity in natural language, in the preferred language.

→
Step 2

Skill Orchestration

A deterministic router selects the correct business or technical skill.

→
Step 3

Validation & State

Structured outputs update the IdeaCase, validation result, and gate status.

Step 4

Persistence

Idea state, decision logs, and artifacts are written to PostgreSQL and Blob.

→
Step 5

Context Enrichment

Relevant documents, session memory, and tenant context are retrieved and refreshed.

→
Step 6

Architecture Deliverables

The platform produces architecture package, diagrams, and session summaries.

3. Components

Frontend

React + Vite UI with guided forms, conversation-like interactions, and role-aware views.

  • Business intake experience
  • Technical review experience
  • Admin / governance experience

API & Orchestration

FastAPI provides the orchestration layer and exposes endpoints for conversation, state, and artifacts.

  • Stage transitions
  • Agent routing
  • Prompt and telemetry hooks

Skill Registry

Central registry of domain skills, deterministic prompts, and versioned instructions.

  • Business Intake Skill
  • Business Viability Skill
  • Technical Validation Skill
  • Response Composer

AI Layer

Azure OpenAI / Foundry models provide reasoning, summarization, and localized response generation.

  • Language detection
  • Canonicalization
  • Response localization
The architecture favors a single conversational surface for the user, while internally the platform routes to specialized skills and agents.

4. Data & Persistence

PostgreSQL Flexible Server

Stores tenant profile, idea state, decisions, prompt versions, and agent telemetry.

Azure Blob Storage

Persists PDFs, exports, evidence, generated architecture artifacts, and conversation packages.

Azure AI Search

Indexes contextual knowledge for hybrid semantic retrieval across documents and sessions.

Persistent Session Intelligence

Session memory enriches the conversation without losing traceability or stage boundaries.

5. Security & Operations

Managed Identity + Key Vault

Secure access between Azure services without embedded secrets.

Observability

Application Insights and Log Analytics capture latency, cost, tokens, quality, and traceability.

Prompt Governance

Prompts are versioned and auditable to keep behavior stable across deployments.

Deployment Model

Azure Container Apps packages frontend, API, and workers into a repeatable cloud-native footprint.

6. Roadmap

Phase Scope Outcome
Phase 1 Idea intake, business validation, case state, simple UI Basic capture and validation
Phase 2 Technical validation, architecture package, response composer End-to-end business + technical flow
Phase 3 Company Context Engine with quick setup and documents Client-specific personalization
Phase 4 Admin center with tokens, cost, ROI, and prompts Governance and FinOps
Phase 5 Multi-tenant IaC and packaged deployment Reusable product for each client

7. Architecture Notes

Why this design works

It keeps the user experience conversational while preserving the machine-readable state needed for enterprise operations.

What is still abstracted

Concrete agent implementation, retrieval policies, and advanced telemetry are intentionally left for later phases.
